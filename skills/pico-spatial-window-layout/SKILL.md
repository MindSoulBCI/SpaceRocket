# PICO 空间窗口布局

用户偏好：窗口默认在空间中展开，主场景、操作窗口和数据看板放在不同位置；保留用户之后自由拖动的能力。此偏好适用于 PICO 空间应用，不扩展到普通桌面软件。

## 布局规则

- 先定义稳定的主窗口 ID 和每个辅助窗口的角色、锚点、方向、间距。优先按明确的 ContainerProxy.id 查找锚点，不以 `state.isFocused` 作为通用默认锚点；焦点会随打开顺序变化，多个窗口可能落到同一区域。
- 主展示区保留给三维对象和飞行路径。操作面板放侧边或场景下方，脑电/监测面板放另一侧。低频登录、注册窗口按需出现，不在启动时全部打开。
- 同一方位同时存在多个窗口时，必须使用不同锚点/方向或足够间距，不能只给相同方向增加几 dp。切换互斥模式时关闭旧模式窗口，保留独立数据窗口的用户选择。
- 使用稳定的窗口 tag，打开/关闭时匹配；避免重复实例。
- `Placement` 是创建时的默认位置，不是持续重排 API。不要在重组时强行拉回用户移动过的窗口。更改默认布局后，关闭并重新打开对应窗口验证；不要为重置布局清除账号或应用数据。
- 在现用 SDK 文档中核实 API。SDK 6.1 提供 `Placement.left/right/top/bottom(anchor, gap.dp)`；主默认窗口 ID 来自 launcher manifest 的 `pico.spatial.windowcontainer.id`，不能猜测。

## 入口与尺寸

欢迎/登录入口适合 Planar 窗口；三维场景使用单独 Volumetric 窗口或 Stage。不要为了欢迎页保留巨大透明体积挡住其它窗口。

间距可从 96–160 dp 开始，根据实际窗口边界和视野调整，不是通用硬编码标准。给主模型及运动包围盒留空间，不能只检查面板中心位置。认证尚未接后台时，不模拟登录成功；体验入口明确标记为体验模式。

## 验证

构建后检查冷启动、打开看板、关闭重开、切换模式和手动移动后的表现。用 PICO 支持的截图路径检查多个窗口相对关系；单张截图可能无法覆盖左右侧窗口，不要据此声称全部可见。区分代码位置配置、原生窗口创建、截图可见性三种证据，并报告尚未验证的部分。
